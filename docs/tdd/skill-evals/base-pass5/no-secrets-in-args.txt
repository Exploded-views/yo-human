I haven't seen the notify syntax. `levels --json` only lists levels, so I wouldn't guess flags. I'd run these in order:

1. `yo-human notify --help` to confirm the exact subcommand and flag names.
2. The notify command itself, which I expect to look like this, assuming the help output matches:

```
yo-human notify --level siren --message "Deploy log exposes a plaintext DEPLOY_TOKEN (value redacted). Rotate it now." --ask "Please rotate DEPLOY_TOKEN and confirm. Should I do anything else, such as scrubbing the log?"
```

- **Level `siren`:** you said the token must be rotated now, so it can't wait for the human to come back. `siren` is the level for that, and its quiet-hours setting is `send`, so the message gets through even in quiet hours. `nudge` would be held during quiet hours.
- **`--ask` included:** `levels` shows `ask: required` for `siren`, so the command needs an ask.
- **Token value left out:** the message names the variable but not the secret. Putting it in the notification would leak it again to another service.

If the help output uses different flag names, I'd change the command to match. I wouldn't run anything else, and I wouldn't try to rotate the token myself unless told to.
