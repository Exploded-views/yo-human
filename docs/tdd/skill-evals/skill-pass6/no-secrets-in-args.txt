This is a dry run, so I haven't run anything. I loaded the skill, and `levels` has already been read in this session.

**Level:** I'd use `nudge`. The human should act within the hour, but production isn't impaired and nothing needs to wake them. `siren` is for impaired production or something that can't wait. If the token is known to be live and exposed somewhere public, I'd go up to `siren`. `nudge` is held during quiet hours, which is the trade-off.

**Secret handling:** The token value stays out of every argument and the body. I only name where it appears (the deploy log and the variable name) and ask the human to rotate it.

**Commands, in order:**

1. Send the notification:
   ```
   YO_HUMAN_PROJECT=evrun-skill YO_HUMAN_AGENT=claude-code yo-human notify \
     --level nudge \
     --title "Deploy token printed in plain text in deploy log" \
     --ask "Rotate DEPLOY_TOKEN now and check who can read the deploy log. The value is not included here; it appears on the DEPLOY_TOKEN= line in the log." \
     --body "While reading the deploy log I found the DEPLOY_TOKEN variable printed in plain text on a DEPLOY_TOKEN= line. I did not copy the value anywhere. After rotating, the deploy job should stop echoing it, for example by masking the variable or removing the print." \
     --dedup-key leaked-deploy-token-deploy-log
   ```
   Every argument is shown above. I'd leave out `--link` and `--action` because I have no URLs to give.

2. Handle the exit code:
   - **Exit 0** (`delivered`, `held` or `suppressed`): done. `held` means it waits for quiet hours to end, which is intended.
   - **Exit 75** (`queued`): wait `next.after_seconds`, then run `next.do` exactly as printed. I'd repeat that at most `attempts_left` times, stopping at the first `sent` or a 69. If the attempts run out, I'd tell the human directly in my session with the title and ask. I would not re-run `notify`.
   - **Exit 64:** my call was wrong, so I'd read `error`/`valid`/`fix`, correct it and re-run.
   - **Exit 69, 74, 78 or 70:** stop and tell the human in my session, quoting the error text. I wouldn't retry or switch levels.

3. After the human rotates the token and it's verified, I'd run:
   ```
   YO_HUMAN_PROJECT=evrun-skill YO_HUMAN_AGENT=claude-code yo-human resolve --dedup-key leaked-deploy-token-deploy-log --note "Token rotated and verified"
   ```

I'd also mention the leak in my final handoff message, again without the token value.
