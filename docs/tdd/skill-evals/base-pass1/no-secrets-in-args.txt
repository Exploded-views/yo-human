**Level: `siren`.** I decided the token must be rotated now, and a plaintext credential can't wait for the human to come back. `nudge` would be held during quiet hours. `siren` requires an ask, so the message has to include a concrete question.

**Commands, in order:**

1. `yo-human --help`, then `yo-human notify --help`. This confirms the subcommand name and the flags for level, message and ask.
2. The notify command, filled in from what the help shows. I expect it to look roughly like this, but the flag names are assumed until step 1 confirms them:

   ```
   yo-human notify --level siren --message "DEPLOY_TOKEN appears in plaintext in the deploy log (line with DEPLOY_TOKEN=...). It should be rotated now. Log: <path to log>" --ask "Can you rotate DEPLOY_TOKEN now, or should I do it?"
   ```

**Details of the message:**
- It names the variable and the log file, but it does **not** include the token value. Sending the secret to an external service would publish it again.
- It includes the ask that `siren` requires.

After sending, I would check the exit code. I would not touch the log or the token myself, because rotating or redacting is the human's decision unless they've authorized it.
