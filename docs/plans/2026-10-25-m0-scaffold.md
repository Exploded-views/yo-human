# M0 Scaffold Implementation Plan

> **Execution (owner, 2026-10-25):** subagent-driven. Wave 3 (Tasks 3–8) runs as parallel lanes. Pre-commit stays lefthook, as the constitution says.
>
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every gate the constitution names exists and runs in CI, proven against a one-command Go program, before any product code.

**Architecture:** One Go module with a `version` command as the only behaviour. A Makefile is the single entry point (`make ci` = what CI runs). Two small Go tools in `tools/` enforce the coverage and perf ratchets, crewkit's stdlib `check-workflows.py` is vendored and pinned by sha256, and a Go test enforces the 400-line limit.

**Tech Stack:** Go 1.27.3; golangci-lint v2.14.0, govulncheck v1.8.0, gitleaks v8.30.1, lefthook v2.2.2 (all `go install`ed by `make tools`, pinned exactly); GitHub Actions `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1), `actions/setup-go@b7ad1dad31e06c5925ef5d2fc7ad053ef454303e` (v7.0.0); Python 3 (preinstalled on runners) for the workflow lint.

**Spec:** [../../constitution.md](../../constitution.md) (Principles I–IV, VII, VIII, X and the Development Workflow). Order and lanes: [2026-10-25-roadmap.md](2026-10-25-roadmap.md).

## Global Constraints

- Module path: `github.com/Exploded-views/yo-human`. Binary: `yo-human`, built to `dist/yo-human` with `CGO_ENABLED=0 -trimpath`.
- `env: GOTOOLCHAIN: local` in every workflow; `go-version: "1.27.3"`.
- Every `uses:` pinned to a full 40-hex SHA with the tag in a comment; `runs-on` only `ubuntu-latest` or `macos-latest`; no `pull_request_target`; `permissions: { contents: read }`; checkout with `persist-credentials: false`.
- Exit codes, as in bitc: 0 ok, 1 check failed (tools only), 2 tool usage or bad input (tools only); the `yo-human` CLI itself uses 64 for usage.
- Go source files ≤ 400 lines (test files included; `testdata/` and generated files exempt); cyclomatic complexity ≤ 10.
- RED proof for every test-first step goes in `docs/tdd/<topic>-red.txt` and is listed in `docs/tdd/README.md` (crewkit's convention). Mutation results go in `docs/tdd/<topic>-mutants.txt`. A mutant that doesn't compile is rejected, not counted as killed.
- No secret values in any output, fixture or RED record. Fake values only (`R0UTING-KEY-FAKE`, `example.com`).
- Makefile recipes must work with the stock tools on macOS and Ubuntu: `shasum -a 256` (not `sha256sum`), no `sed -i`.
- One commit per step marked Commit; conventional commits with a scope; the RED commit says `(RED)` in its subject.

## Review Focus

1. **A new package with no tests is silently ignored by the coverage ratchet.** `go test -coverprofile` omits packages with no test files, so the check must compare against `go list ./...`, not just the profile. Pinned in Task 4 by `TestCheckPackageWithoutCoverageFails`.
2. **The floor comparison on a brand-new branch or first floors file fails open.** It must compare a PR with its merge base and a push with `github.event.before`, and only skip when there is genuinely no base. Pinned in Task 4 Step 7 (the CI step is copied from crewkit's fail-closed version, plus a verification run).
3. **The secret scan prints the secret it found.** Pinned in Task 6 Step 4: a planted fake key on a throwaway branch must report the rule id, file and commit only.
4. **Perf budgets that pass on a laptop flake on shared runners.** Budgets are measured on the runner, and `ci_headroom` applies only when `CI=true`. Pinned in Task 5 by `TestHeadroomOnlyInCI`.
5. **A Makefile target that works on Ubuntu and breaks on macOS.** The `test` job runs on both; Task 2 runs every Makefile target on the macOS runner, not only `go test`.
