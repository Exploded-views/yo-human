# U2 Heeler Fork Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Once a week, upstream Heeler is merged into a sync branch on our fork, and one PR with a Claude-written summary is opened or updated. Nothing ever merges a PR or pushes to `main`.

**Architecture:** One workflow on the fork's `main`, `.github/workflows/upstream-sync.yml`, plus a tested merge script, `.github/scripts/upstream-sync-merge.sh`. Two jobs:
- **`summarize`** has a read-only token and is the only job holding the Claude secret.
  - It merges upstream in a **separate worktree** with the script, which refuses conflicts and upstream changes to `.github/`, `.claude/` and `.mcp.json`.
  - Claude then runs in the **clean checkout of `main`**, so it loads no upstream config. It has no shell and no file writes, may read only `sync-work/` (the merge's text outputs), and returns the description as structured output (`--json-schema`).
  - The description is refused if it contains the token or an `sk-ant-` key, and a fixed note is appended. The job then hands it on as an artifact.
- **`publish`** has a write token, no secrets and no Claude. It checks Claude's text against Heeler's attribution rules, repeats the merge on a fresh branch `sync/upstream-<sha12>` from `main`, pushes it with the workflow token, opens its PR, and closes the previous sync PR (this repo's own only) as superseded.

**Tech Stack:** GitHub Actions (`ubuntu-latest`). Pins:

**Spec:** Owner, 2026-10-26: "sync once per week. and when it does use claude to do the sync and open a PR." Design doc, "Decided by the owner": a sync PR that never merges. Issues are off on the fork, so the summary lives in the PR body. Constitution GitHub rules. Issue: #47.

**Design change after a security review (2026-10-26).** The first version let Claude run git and `gh` itself and push with the Claude App token. A review found two problems:
- Pushes made with an app token do start workflows, so upstream code pushed to a fork branch could run with the fork's secrets.
- Wildcard tool rules (`git diff:*`, `gh pr edit:*`) let a prompt hidden in upstream text do more than intended.

Now Claude writes only the description, and deterministic steps do the sync and the PR. This is still one run per week, and Claude still writes what the owner reads.

A second review then found three more problems, all fixed:
- Claude ran inside the merged tree, so upstream `.claude/settings.json` hooks or `.mcp.json` servers could have run beside the token.
- Read and Write reached outside the inputs: Read could open `/proc/self/environ`, which holds the token.
- The `.github/` check grepped git's listing, which quotes unusual filenames. It now uses pathspecs.

A third review found that Claude still wrote the "Review carefully" list, so a prompt hidden in upstream text could hide a risky file. Claude now writes only two sections: the summary and the yo-human relevance note, capped at 8000 characters, with any other heading dropped. The workflow builds everything a reviewer relies on from git's output with fixed patterns: the review list, the commits, all changed paths, and a notice when the diff given to Claude was cut.

A fourth review found three more problems, all fixed:
- The review list was a grep of git's listing, which misses names git quotes. The merge script now writes `review.txt` with pathspecs.
- Claude's summary was rendered as raw Markdown and HTML, so an unclosed `<!--` could hide the sections after it.
- Commit subjects went in unescaped.

The workflow's sections now come first; paths and commit subjects appear only in code spans; Claude's summary comes last, HTML-escaped and quoted.

A fifth review (code review on fork PR #2) found eight real problems, all fixed:
- the rolling branch could need to push workflow files
- lists were computed against the sync branch instead of `main`
- `--head sync/upstream` also matched a stranger's PR from their own fork
- squash merges stall the merge base
- the description had no size bound
- Markdown in Claude's text took effect (it now sits in a code block)
- upstream paths with `@` could trip the attribution check (only Claude's text is checked now)
- an empty summary passed

It also flagged two things that need no change: the label it called missing exists, and no CI runs on sync PRs, which is the accepted cost of keeping upstream code away from secrets; the PR body says so.

## Global Constraints

- Triggers: `schedule` (`17 13 * * 1`) and `workflow_dispatch` only. Job guard: `github.repository == 'Exploded-views/Heeler'`.
- The secret `CLAUDE_CODE_OAUTH_TOKEN` appears only in `summarize`, whose token is `contents: read`. `publish` gets `contents: write` and `pull-requests: write`, and no secrets.
- The push and the PR use the workflow token. GitHub starts no workflow runs from events that token creates, and it can't change workflow files.
- Any upstream change under `.github/`, `.claude/` or `.mcp.json` fails the run; the owner syncs that week by hand after reading those files. Once merged, they run on the fork, where the token is stored. Every sync PR carries a fixed note saying so.
- One fresh branch per upstream commit, `sync/upstream-<sha12>`, made from `main`, so a sync PR never carries `main`'s own changes (the workflow token can't push workflow files) and every list is exactly what the PR adds. A commit already proposed is skipped. At most one open sync PR; never a force push.
- Sync PRs merge with a merge commit only; syncing by hand means merging the upstream commit, never cherry-picking. Otherwise the merge base stalls and the next sync re-lists old commits.
- Every `uses:` pinned by full SHA; passes crewkit's `check-workflows.py` (sha256 `3e63a79ede7c395e10d1ad68603c7220653823f0a5a7681a112709595a1b96e4`). <!-- scrub:pinned-hash -->
- Heeler's CI rejects a `Co-authored-by` trailer, "generated by" text or an email address in commits, PR titles and PR bodies. The prompt forbids them, `publish` checks the description with Heeler's own script, and our commits on the fork and upstream (U2–U6) carry no Claude attribution lines.

## Review Focus

1. **Claude is prompt-injected by upstream text.** With no shell, no writes and reads limited to `sync-work/`, the worst outcome is a misleading summary. The review list, commit list and changed paths are built by the workflow, not Claude, and are the ground truth to check the summary against.
2. **Upstream changes a workflow.** The merge script refuses it (tested). That week shows a failed run, which GitHub emails the owner about.
3. **A merge conflict.** The script aborts cleanly and pushes nothing (tested); the run fails visibly.
4. **Last week's sync PR is still open.** This week's branch starts again from `main`, and its lists include last week's unmerged commits (tested). `publish` opens the new PR, then closes the old one as superseded.
5. **Upstream contribution branches pick up fork-only files.** U3–U6 branches are cut from upstream `main`, never the fork's `main`. This is in the PR footer and the U3–U6 issues.
